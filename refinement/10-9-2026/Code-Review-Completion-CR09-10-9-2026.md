## 2. CR09-01: capture SSRF boundary

- Added a per-capture HTTP proxy bound to an ephemeral loopback port. Both Chromium and Playwright's request client use this proxy.
- The proxy resolves each destination when opening the upstream connection, applies the blocked-address policy, and connects to the exact validated IP. A DNS change between route validation and connection can no longer redirect the socket to a private address.
- Removed the guarded-request fallback that continued a request after `route.fetch()` failed. Rejected or failed guarded requests abort closed.
- Navigation redirects are fetched one hop at a time. The capture contract starts main navigation with GET; an allowed redirect is converted to a new browser GET navigation so context routing validates every hop and the configured redirect limit is enforced before the next connection. Final URL, origin, and relative resources were verified in a real Chromium test.
- Other browser traffic, including resource requests and non-GET traffic generated by a page, retains Chromium's HTTP behavior while every socket remains constrained by the validating proxy.
- Popup first requests are guarded even when Playwright has not attached a frame object. Proxy enforcement remains the final connection boundary for all pages in the BrowserContext.
- Proxy rejections are mapped back to `SsrfBlockedError` or `DnsResolutionError`, preserving security versus availability classification.

Browser integration coverage proves that an allowed redirect reaches the intended final URL and relative image, while private redirect destinations, the hop beyond `REDIRECT_LIMIT`, popup redirect destinations, and a DNS-rebinding private address receive zero requests.

## 3. CR09-05: exact comparison metadata and approval

- Added `GET /snapshots/{id}` consumption and a snapshot metadata query keyed by the exact snapshot ID from the latest `CheckResult`.
- The comparison card now derives baseline image, current image, metadata, score, and approval action from the same two IDs. It no longer substitutes the newest cached snapshot when exact metadata is absent.
- Approval is available only when exact current snapshot metadata exists, is not already a baseline, and differs from the comparison baseline. The button displays the snapshot ID it will approve.
- If the target's current state is `Failed` or `Availability Issue`, the retained successful result is labelled `Last Successful Comparison` with its result time.
- Tests cover absent exact metadata and the historical-result label, in addition to the existing cache and detail-page paths.
